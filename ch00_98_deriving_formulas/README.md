# Chapter 0.98 · 公式是怎么被推出来的

配套文章：[`docs/math_his_cha0_98_derivation.md`](../docs/math_his_cha0_98_derivation.md)

> 上一章（0.6）讲**怎么读一个陌生公式**；这一章讲**怎么从零把它推出来** ——
> 从「数学消费者」变成「数学生产者」的那一步。

## 一句话总纲

**推导只有两类合法动作：**

| 类型 | 做什么 | 信息量 | 可逆 | 验收方式 |
|------|-------|-------|------|---------|
| **A · 恒等变换** | 换一件衣服，内容一样 | 不变 | ✅ | `simplify(左-右) == 0`，机器可验 |
| **B · 引入新信息** | 塞进一条物理/假设/近似 | 增加 | ❌ | 报出前提与误差阶 |

**课本最大的罪过，是把 B 类动作伪装成 A 类。**「注意到……」四个字后面，往往藏着一整条物理定律。

## Lean 4 证明（只用 core，**不需要 mathlib**）

```bash
lean ch00_98_deriving_formulas/GaussSum.lean     # 无输出 = 全部证明通过
```

Python + SymPy 只能说「我算了一遍，没发现问题」。
Lean 要求你交出一个**证明对象** —— 编译通过 = 对所有取值都成立。
更重要的是它会**逼出被省略的前提**：纸笔推导允许你「不写出来」，Lean 不允许。

| 文件 | 对应章节 | 讲什么 |
|------|---------|-------|
| `CompletingSquare.lean` | 0.98.2 | 配方恒等式、求根的 ⟺ 等价、花拉子米原题的两个根 —— A 类动作的机器验收 |
| `GaussSum.lean` | 0.98.2 #11 | 归纳法：高斯求和 / 奇数和 / 平方和，三条公式的证明**长得一模一样** |
| `Telescoping.lean` | 0.98.2 | 裂项相消 = 离散版微积分基本定理；换一个 $f$ 就出一条新求和公式 |
| `CancelFallacy.lean` | 0.98.5 | 除以零：**Lean 根本不让你写出那一步**，除非先交出 `a - b ≠ 0` |
| `PhotonBox.lean` | 0.98.3 路线 B | $E=mc^2$ 光子盒推导的形式化；`hL : L ≠ 0` 就是那条被省略的前提 |
| `DimensionTypes.lean` | 0.98.6 | 量纲即类型：`E = mc²` 编译通过，`E = mc` 和 `m + c` **编译失败** |

> **本地环境**：Lean 4.32.2（elan 管理）。这些文件只用 Lean core 的
> `grind` / `induction` / `decide` / `Int.eq_of_mul_eq_mul_right`，
> 不引入 mathlib，所以 `lean <file>` 可以直接跑，无需 `lake build`。

### 三种严格程度，成本递增

| 方式 | 成本 | 什么时候发现错误 |
|------|------|----------------|
| 纸笔靠自觉 | 最便宜 | 往往永远不发现（火星气候轨道器） |
| Python + SymPy 运行时对拍 | 便宜 | 跑到了才发现 |
| Lean 编译期检查 | 贵一点 | **写错了根本编不过** |

## 选路心法（0.98.7）

1. **先盯着终点看** —— 不知道目标长什么样，就不知道该往哪化简（波利亚逆向工作法）
2. **每个等式都要报来源** —— 不是守恒律，就是对称性、定义、或实验事实
3. **数未知数、数方程** —— 卡住时先判断：是信息不够（该找物理），还是没整理出来（该做代数）
4. **先做特例，再做一般** —— 特例里那个「哦原来是这样」的瞬间，就是一般情形的证明骨架
